    Class NFCAccessManagement

    Handles the NFCAccess service of a lock: the part of Apple Home Key which runs over HomeKit. The Home app hands the lock a reader key, and the public key of the home key on each phone and watch.

    This is only half of Home Key. The other half is the NFC reader at the door, which talks to the phone with those keys. HAP-NodeJS has no part in that: without a reader, the key shows in Wallet and opens nothing.

    Listen for NFCAccessManagementEvent.STATE_UPDATED to save the state and to hand it to the reader, and pass the saved state back as NFCAccessManagementOptions.state on the next start.

    The state holds a private key. Save it in a file of your own which nobody has a reason to share. A Homebridge plugin must not put it in the context of the accessory: that is written to the cachedAccessories file, which people post in bug reports.

    The lock also needs a LockMechanism service, and the colour of the card comes from the Hardware Finish characteristic of the AccessoryInformation service: see encodeHardwareFinish.

    HomeKit does not document this service. The layout comes from Apple's own HomeKit code, and the handling of reader keys and device credential keys matches the plugin homebridge-fake-homekey. The handling of issuer keys and the answers to a list of device credential keys are not confirmed against a Home app.

    Example

    // an accessory restored from the cache already has the service: hand it over, so no second one is added
    const cachedService = accessory.getService(Service.NFCAccess);
    const nfcAccess = new NFCAccessManagement({ state: savedState, service: cachedService });
    if (!cachedService) {
      accessory.addService(nfcAccess.getService());
    }
    accessory.getService(Service.AccessoryInformation)!
      .setCharacteristic(Characteristic.HardwareFinish, encodeHardwareFinish(HomeKeyFinish.TAN));

    nfcAccess.on(NFCAccessManagementEvent.STATE_UPDATED, (state) => {
      // save the state in a file of your own (not in the accessory context), and hand it to the NFC reader
    });
